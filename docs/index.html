Any-prompt engine — v4.3.0

Works on every prompt in the world

Previous interpretability tools only worked on IOI-style name-swap tasks. Glassbox 4.3 auto-selects the right corruption strategy for any text domain — maximising causal signal regardless of prompt type.

  • Entity swap for named-entity prompts (Wang et al. 2022)
  • Semantic antonym for binary decisions (Gurnee & Tegmark 2023)
  • Modal negation for instruction-following (Geiger et al. 2023)
  • Random token masking as universal fallback (Meng et al. 2022)

Billion-parameter support — v4.3.0

Llama-3-70B. Mistral. Gemma. Any size.

Gradient checkpointing (Chen et al. 2016) reduces peak activation memory by √n_layers — 11× for 80-layer models. CPU offloading handles 70B+ on a single GPU. Estimate VRAM before loading.

  • Gradient checkpointing: O(√n) memory, +33% compute
  • CPU offloading for 70B+ (ZeRO-Offload, Rajbhandari 2020)
  • estimate_memory() predicts VRAM requirement upfront
  • bfloat16 support halves VRAM with negligible precision loss
Large model usage 
from glassbox.large_model import analyze_large, estimate_memory

# Check VRAM before loading (Kaplan 2020: n_params ≈ 12Ld²)
mem = estimate_memory(n_layers=80, d_model=8192)
# → "106 GB attribution pass → use checkpoint+offload"

# Drop-in replacement for gb.analyze()
result = analyze_large(
    gb,
    "Loan decision:", " Approved", " Denied",
    strategy="auto",       # selects checkpoint+offload
    dtype=torch.bfloat16,  # 106 GB → 53 GB
