# Glassbox — Faithful Decision-Audit Plan (living document)

**Status:** active · **Owner:** Ajay Pravin Mahale · **Started:** June 2026
**This is the source of truth.** Every phase below is executed in order, each task
passes the *Pre-Implementation Cross-Check Gate* before it is run, and every result
is logged in the *Decision & Audit Log* at the bottom with its provenance and a
verifiable reference. Nothing is asserted that has not been measured or cited.

---

## 0. North Star

> Prove, on a **legally clean** and **ground-truth-validated** basis, that Glassbox
> can audit a model that actually makes a real-world decision (credit first), recover
> the circuit that implements that decision, measure its faithfulness honestly, and
> emit the EU AI Act Annex IV documentation — turning the Bosch-style pitch from a
> claim into a reproducible worked example.

**Why this and not something else.** Our single biggest gap today (confirmed in the
demo) is that raw GPT-2 only passes the toy IOI task; every real sector honestly
returns NON-COMPLIANT because the *model* can't do the task. The highest-leverage
move is therefore to create a **real decision model** as an audit target. Doing it
with a **self-generated, known decision rule** also gives us something stronger than
any marketing demo: a **ground-truth check on faithfulness** (we know the true rule,
so we can verify the discovered circuit implements it).

### Success criteria (measurable, honest)
1. A reproducible pipeline: synthetic data → fine-tuned small model → Glassbox audit →
   Annex IV file, runnable end-to-end from one notebook, fixed seeds.
2. The fine-tuned model demonstrably **learned the rule** (held-out accuracy reported).
3. A faithfulness result **reported as measured** — whatever grade it is. A Grade C is
   an acceptable, publishable outcome; a fabricated Grade A is not.
4. A **ground-truth faithfulness check**: ablating the discovered circuit flips the
   decision on rule-relevant inputs more than on irrelevant ones (quantified).
5. Every dataset and method carries a provenance entry and a verifiable citation.

## 1. Non-negotiable guardrails

These override convenience, deadlines, and "it would look better if." If a guardrail
and a goal conflict, the guardrail wins.

### 1.1 Legal / data
- **Only** use data that is (a) self-generated (we own it), (b) CC0 / public domain,
  or (c) CC BY / CC BY-SA with attribution. Nothing else.
- **No** web scraping, no Kaggle "competition-use-only" data, no Lending Club mirrors,
  no dataset without an explicit license.
- **No real personal or patient data, ever.** Healthcare uses synthetic only.
- License interpretation is **verified at the source page** before use and recorded in
  the Data Provenance Register. *We are not lawyers; if a license is ambiguous, we
  skip the dataset.*

### 1.2 Honesty / science
- Every number is **measured and reproduced**, never estimated to look good.
- **Report failures.** "The model is accurate but the circuit is only Grade C" is a
  real finding and ships as-is.
- **No fabricated citations, numbers, or sources.** Every reference is checked against
  the primary source before it is used in a public artifact.
- Distinguish **faithfulness from plausibility** and from **accuracy** at all times
  (Jacovi & Goldberg 2020; see References).

### 1.3 Engineering
- Fixed random seeds; deterministic where possible; environment + versions recorded.
- Test-first for any reusable code; reproducibility is an acceptance criterion, not a
  nice-to-have.
- The audited model must be **open-weight, loadable in TransformerLens, ≤ 7B** (the
  gradient-based attribution memory ceiling on a 40 GB A100; see VALIDATION_LOG.md).

### 1.4 Audit trail
- Every dataset → Data Provenance Register (where, license, why, how used).
- Every method → References Register (peer-reviewed, with venue).
- Every executed step → Decision & Audit Log (what, result, seed, reference).

## 2. Pre-Implementation Cross-Check Gate

**No task is implemented until all five boxes are ticked and recorded in its log entry.**

1. **Plan fit** — the task is in this plan (or the plan is updated first, with reason).
2. **Reference** — the method has a cited, verified peer-reviewed source; the data has
   a verified license entry.
3. **Legality** — passes §1.1 (license / no-PII).
4. **Reproducibility** — seed fixed, environment recorded, expected output stated.
5. **Honesty** — the expected output is reported as-measured; no number is pre-assumed.

If any box fails → stop, fix, or escalate to the user. This gate *is* the "cross-check
before implementation" requirement.

## 5. Phased plan

Each task: **What → Why → How → Acceptance → Refs → Risk.** Tasks run top-to-bottom.

### Phase 0 — Close the loop (fast, removes loose ends)
- **0.1 Redeploy the website.** *Why:* public face must match the reconciled honest
  numbers in case anyone (incl. Bosch) looks now. *How:* confirm the last push
  triggered Vercel; open the live site; verify IOI/credit/scale/speed render. *Accept:*
  live site == repo numbers. *Risk:* low.
- **0.2 Defer v4.5.1.** Hold the PyPI release so it can *bundle* the Phase-1 worked
  example. *Accept:* decision recorded (this line).

### Phase 1 — Synthetic ground-truth credit experiment (the core)
- **1.1 Define the credit rule.** *What:* a transparent deterministic rule, e.g.
  `approve ⇔ (score ≥ 640) ∧ (dti < 0.40) ∧ (defaults = 0)`. *Why:* known truth →
  faithfulness can be validated, not just measured. *How:* write it down in this doc +
  the generator. *Accept:* rule documented, deterministic. *Refs:* n/a. *Risk:* low.
- **1.2 Generate D1 (synthetic credit).** *How:* scripted, seeded, documented schema +
  class balance; held-out split. *Accept:* dataset reproducible from seed; we own it.
  *Risk:* rule too easy/trivial → mitigate with noise + realistic feature ranges.
- **1.3 Pick the base model.** Candidates (open-weight, TransformerLens-loadable, ≤3B
  to stay well under the audit ceiling): Pythia-1.4B/2.8B, Qwen2-1.5B, Llama-3.2-1B/3B.
  *Accept:* license checked + loads in TransformerLens. *Refs:* §4. *Risk:* TL support
  gaps → verify load before training.
- **1.4 Fine-tune (LoRA/QLoRA).** *How:* QLoRA on Colab A100; record hyperparams + seed.
  *Accept:* training runs, loss converges. *Refs:* LoRA, QLoRA (§4). *Risk:* overfit →
  hold-out eval.
- **1.5 Merge adapter + verify learning.** *Accept:* held-out accuracy reported (the
  model genuinely makes the decision). *Risk:* low accuracy → iterate before auditing.
- **1.6 Audit with Glassbox.** circuit + suff/comp/F1 + grade + Annex IV file. *Accept:*
  result reported **as measured**, Annex IV emitted. *Refs:* §4. *Risk:* none to honesty.
- **1.7 Ground-truth faithfulness check.** *What:* ablate the discovered circuit and show
  the decision flips more on rule-relevant inputs than irrelevant ones; quantify. *Why:*
  this is the scientific payload — faithfulness validated against known truth. *Accept:*
  a number + plot, honest interpretation. *Refs:* ERASER, causal abstraction (§4).

### Phase 2 — Real-data corroboration (D2, German Credit, CC BY 4.0)
- Repeat 1.3–1.6 on a model fine-tuned on D2; compare circuit/faithfulness to D1.
  *Accept:* documented comparison (agreement or honest divergence). *Refs:* D2 + §4.

### Phase 3 — Generalize (HR synthetic, then health via Synthea)
- HR: D3 synthetic, same pipeline. Health: D4 Synthea **only after license verified**,
  synthetic only. *Accept:* multi-sector worked examples, each honestly graded.

### Phase 4 — Write-up + release
- Honest results write-up (what worked, what didn't); update website with the real
  worked example; **ship v4.5.1** bundling it; optional arXiv erratum/v2 once numbers
  settle. *Accept:* every public number cross-checked against the source run.

## 6. Risks & mitigations
| Risk | Mitigation |
|---|---|
| Fine-tuned demo model mistaken for a production underwriter | Label "demonstration model on synthetic/public data" everywhere |
| Accuracy ≠ faithfulness confusion | State the distinction every time; report both separately |
| License ambiguity | Skip the dataset; prefer self-generated / CC0 / CC BY |
| Audit OOM at scale | Keep audited model ≤ 7B on A100; document the ceiling |
| Citation/number drift into public artifacts | The Cross-Check Gate (§2) + verify-at-source rule |
| Health data risk | Synthetic only; verify Synthea license; no real records |
